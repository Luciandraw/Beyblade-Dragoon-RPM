# USB-прошивальщик для GitHub Pages

Проект подготовлен для публикации, но ещё не опубликован. Основная прошивка не собрана полностью локально: в `docs/firmware/release.json` стоит `ready: false`. Это намеренная блокировка установки, а не демонстрационный бинарник. Диагностические скетчи не публикуются.

## Самый простой путь — GitHub Actions

1. Создайте репозиторий GitHub и загрузите этот проект, включая `main`, `docs`, `scripts` и скрытую папку `.github`. Локальные `.build*`, `.module-check` и `.arduino-build-libs` загружать не нужно. Перед публичной загрузкой просмотрите исходники на наличие личных данных.
2. В репозитории откройте **Settings → Pages → Source → GitHub Actions**.
3. Откройте **Actions → Build and publish USB installer → Run workflow**. Workflow должен находиться в основной ветке репозитория. Введите версию, например `1.0.0-test1`.
4. Для первого запуска оставьте публикацию выключенной. GitHub соберёт именно `main` и предоставит архив `beyblade-usb-installer` со страницей и бинарником. Сборка может занять десятки минут; ошибки видны в журнале Actions.
5. Проверьте полученную прошивку на своей плате. Успешная компиляция и проверка заголовков не гарантируют аппаратную работоспособность или точность RPM.
6. Для публикации запустите workflow с включённым **Publish publicly to GitHub Pages after building**. Он пересоберёт выбранную ревизию; используйте ту же проверенную ревизию исходников. Ссылка появится в шаге deploy и в Settings → Pages. Обычно это `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Никаких личных токенов в файлы добавлять не требуется: workflow использует ограниченные стандартные разрешения GitHub. Публикация никогда не запускается автоматически при push. Если сборка или проверка образа не удалась, deploy не выполняется и предыдущая публикация остаётся.

## Вариант с Arduino IDE

Соберите `main` профилем **Waveshare ESP32-S3-Zero**, ESP32 core **3.3.11**, Flash Mode **QIO 80 MHz**, PSRAM **Enabled**, USB Mode **Hardware CDC and JTAG**, USB CDC On Boot **Enabled**. В IDE выберите **Sketch → Export Compiled Binary**. Найдите `main.ino.merged.bin` в папке экспорта. Не используйте обычный `main.ino.bin` или один `bootloader.bin`.

Установите Node.js 22 или новее. Из корня проекта выполните:

```powershell
node scripts/prepare-web-release.mjs "ПУТЬ-К-ПАПКЕ-С-MERGED-BIN" "1.0.0"
node --test scripts/web-release.test.mjs
```

Скрипт создаст бинарник с версией и хешем в имени, `manifest.json` и `release.json` в `docs/firmware`. Он проверяет размер, семейство ESP32-S3, заголовок Flash и расположение загрузчика, таблицы разделов и приложения. Это структурная проверка, не цифровая подпись и не аппаратный тест.

Затем можно загрузить обновлённую папку `docs` в репозиторий и выбрать **Settings → Pages → Deploy from a branch → main → /docs** вместо Actions. Не смешивайте два способа публикации. Все ссылки относительные: сайт работает и внутри пути репозитория.

## Предпросмотр

Не открывайте `index.html` через `file://`. При установленном Python:

```powershell
python -m http.server 8080 --bind 127.0.0.1 --directory docs
```

Откройте `http://localhost:8080`. На GitHub Pages используйте HTTPS. Если прошивка ещё не подготовлена, страница честно показывает её отсутствие и не открывает USB-порт.

## Важные ограничения

- Только ESP32-S3-Zero, Flash 4 MB, QSPI PSRAM и распиновка из `main/config.h`. Проверка семейства ESP32-S3 не определяет модель платы или разводку.
- Это полная установка с очисткой памяти. История, рекорды и настройки удаляются. Merged-образ также содержит заполнение промежутков Flash, поэтому сохранение NVS не обещается.
- Готовый merged-образ Arduino 3.3.11 уже содержит правильные адреса. Для S3 загрузчик начинается с `0x0`, разделы с `0x8000`, приложение с `0x10000`. Заголовок DIO у загрузчика, собранного профилем QIO, ожидаем: загрузчик затем настраивает QIO. Не меняйте байты вручную.
- Сайт использует ESP Web Tools **10.1.1** с CDN unpkg; требуется доступ в интернет. Перед USB-подключением браузер проверяет SHA-256 скачанного бинарника и передаёт установщику именно проверенный буфер. Это проверка целостности, не защита от подмены всего сайта.
- Открытие страницы ничего не прошивает. Нужно подтвердить очистку, нажать кнопку, выбрать порт и подтвердить установку в диалоге ESP Web Tools. Интерфейс библиотеки может быть английским.
- Если не удаётся подключиться: закройте Serial Monitor, зажмите BOOT, нажмите RESET, отпустите BOOT и повторно выберите порт. После записи нажмите RESET.

Документация: [ESP Web Tools](https://esphome.github.io/esp-web-tools/), [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-github-pages-to-showcase-your-work).
